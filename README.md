# StaffHub

**StaffHub** — это десктопное приложение для управления сотрудниками, контрагентами и заказами. Приложение построено на современных технологиях .NET с соблюдением принципов чистой архитектуры.

## Описание задачи (ТЗ)
Реализовать десктопное приложение со следующим функционалом:
- Отображение сущностей в виде таблицы.
- Добавление, просмотр и редактирование сущности в отдельном виджете (модальной форме).
- Удаление сущности.

**Сущности в системе:**
- **Сотрудник**: Фамилия, Имя, Отчество (выделено из ФИО по правилам нормализации 1NF), Должность (`enum`: Руководитель, Работник), Дата рождения.
- **Контрагент**: Наименование, ИНН, Куратор (Сотрудник).
- **Заказ**: Дата, Сумма, Сотрудник, Контрагент.

## Используемый стек технологий
* **Платформа**: .NET 10.0
* **Пользовательский интерфейс (UI)**: WPF (Windows Presentation Foundation)
* **Архитектурный паттерн**: MVVM (через библиотеку `CommunityToolkit.Mvvm`)
* **ORM**: NHibernate
* **База данных**: MySQL / MariaDB
* **Внедрение зависимостей (DI)**: `Microsoft.Extensions.DependencyInjection`

## Архитектура и паттерны проектирования

Приложение разделено на три слабосвязанных слоя:

### 1. StaffHub.Core (Доменная модель)
Содержит бизнес-логику приложения, абстракции и интерфейсы, не зависящие от способа хранения данных или пользовательского интерфейса.
- **Сущности (Entities)**: `Employee`, `Counterparty`, `Order`, наследуемые от абстрактного класса `EntityBase` (предоставляет поля `Id` и `IsDeleted` для мягкого удаления).
- **Интерфейсы**: Определен универсальный интерфейс `IRepository<T>`, абстрагирующий работу с данными.

### 2. StaffHub.Database (Доступ к данным)
Слой, отвечающий за связь с БД с использованием ORM **NHibernate**.
- **Маппинги**: Классы-конфигурации (например, `EmployeeMap`), использующие Code-First подход (`Mapping.ByCode`) для связывания C#-сущностей с таблицами MySQL. Настроена "жадная" загрузка (Eager Loading через JOIN) для устранения проблемы N+1 запросов.
- **Паттерн "Репозиторий"**: Универсальный класс `Repository<T>`, реализующий CRUD операции и логику мягкого удаления (Soft Delete), когда запись не стирается жестко из БД, а помечается флагом `IsDeleted = true`.

### 3. StaffHub.Application (UI)
Презентационный слой на базе **WPF**.
- **Паттерн MVVM**: Строгое разделение визуальной части (Views) от логики (ViewModels).
  - Свойства и команды реализуются с помощью пакета `CommunityToolkit.Mvvm` (`ObservableObject`, `[RelayCommand]`).
  - Данные привязываются к таблицам (`DataGrid`) и формам-виджетам.
- **Валидация данных**: Внедрена проверка вводимых данных на уровне ViewModels (с помощью `ObservableValidator` и `DataAnnotations`). Присутствует защита от ввода цифр в ФИО и детальная проверка контрольных сумм ИНН (на 10 и 12 символов). Ошибки отображаются прямо в XAML-интерфейсе, блокируя кнопку сохранения.
- **Dependency Injection (DI)**: Точка входа приложения (`App.xaml.cs`) инициализирует глобальный DI-контейнер (`ServiceCollection`). Контейнер автоматически регистрирует NHibernate-сессии (`ISession`), репозитории и предоставляет все зависимости прямо в конструкторы ViewModels.

## Структура БД (SQL)
Для ручного развертывания структуры предусмотрен файл `create_tables.sql` в корне репозитория. В нем описаны таблицы `Employees`, `Counterparties` и `Orders` с соответствующими внешними ключами (`FOREIGN KEY`) и правилами их обработки (`ON DELETE SET NULL` / `RESTRICT`).

## Запуск приложения
1. Склонируйте репозиторий.
2. Проверьте настройки подключения к базе данных MySQL в `StaffHub.Database.Extensions.ServiceCollectionExtensions.cs`.
3. Запустите скрипт создания таблиц `create_tables.sql` в вашей СУБД.
4. Выполните сборку и запуск проекта:
```bash
dotnet build
dotnet run --project StaffHub.Application/StaffHub.Application.csproj
```
